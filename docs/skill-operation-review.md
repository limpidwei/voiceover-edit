# voiceover-video-edit 实际运行状况复盘

更新日期：2026-10-29

## 结论

旧版 skill **能自动触发、能跑出成片，但本质上仍是一组高返工脚本**：技术问题会跨项目重复出现，文档、脚本和中间数据格式也逐渐分叉。

本轮打磨后，核心计算已收敛到独立 `voiceover-edit` 包，本地 skill 改为触发、交互和编辑决策的薄壳。当前更准确的评价是：**基础流程可重复、关键错误有自动检查，但完整真实素材验收尚未全部重做，不能宣称“所有场景都已稳定”。**

## 实际案例与触发情况

- 复盘覆盖 12 个口播项目：11 条正式成片和 1 条预览。
- 记录中的 14 次 skill 调用均为自动触发，没有依赖手动斜杠命令，说明基础触发是顺畅的。
- 另有 3 次外部执行只是沿用旧计划和脚本，没有经过 skill，不能计入成功触发。
- 旧 description 同时包含剪辑、发布文案和限流自查，与其他内容/合规 skill 职责重叠。现已收窄到剪辑执行与质检；**收窄后的真实会话命中率仍需继续观察**。

## 哪些已经好用

1. **入口统一**：9 个 CLI 子命令可直接调用，不必再判断该选哪个历史脚本。
2. **基础数据可复用**：统一计划和词格式，减少跨阶段手工转换。
3. **高频字幕错误有回归检查**：时间进位、remap、空隙吸附和显示宽度均有自动化覆盖。
4. **缓存和模型边界更诚实**：参数变化会使验证缓存失效；不存在的模型不再被写成可用回退。
5. **职责更清楚**：skill 管交互和编辑决策，包管计算，内容诊断与发布宣发不再混入。

## 仍不能宣称好用的部分

- 尚未用本轮修复后的版本重新跑完一条长 4K HLG 成片并做人工视觉验收。
- 尚未在 iPhone 上重新验证 4K 播放。
- `verify` 当前比较整片字符覆盖，不是逐条字幕的时间轴对齐证明。
- 结构检查的覆盖率需要独立的编辑后词数据；没有对照时会跳过，不能当作内容完整性的充分条件。
- `cover` 负责抽帧，不负责完整封面排版；xuanfa 是本地可复用依赖，不属于公开包内置能力。
- 跨平台、VFR、AV1/VP9、多音轨混合输入仍属未验证边界。
- 长视频 ASR 仍需要串行和人工校对，不能承诺无人值守。

## 总体判断

**已经从“每次靠经验救场”进步到“核心规则可复用、部分错误能自动拦截”，但还处于需要真实成片继续校准的阶段。** 下一次验收应优先选择一条带中英混排、多个切点的 4K HLG 素材，完整走 probe→plan→ASR→subtitle→render→QC→verify→cover，并把结果补回本文件。
